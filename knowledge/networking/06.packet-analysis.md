# 📚 Wireshark and Packet Analysis

## 📌 Definition

A packet capture and analysis tool that makes every previously abstract networking concept (handshakes, DNS, ARP) directly observable, packet by packet.

## 🧠 Core Concept

Each captured packet's detail pane mirrors the OSI model directly — Ethernet (Layer 2), IP (Layer 3), TCP (Layer 4), and application data (Layer 7) are shown as an expandable tree.

## ⚙️ How It Works

dns # filter: DNS traffic only
tcp.flags.syn == 1 # filter: TCP handshake SYN packets
arp # filter: ARP traffic
tls.handshake.type == 1 # filter: TLS Client Hello packets

Right-click → Follow → TCP Stream reconstructs a full client/server conversation into readable form.

## 🔐 Cybersecurity Relevance

Capturing `tcp.flags.syn == 1` while running a port scanner shows the exact SYN packets the scanner generates, confirming what the tool does under the hood. Modern TLS 1.3 encrypts the certificate exchange, so no separate readable "Certificate" packet appears — a real, current detail that differs from older TLS 1.2 tutorials.

## 💻 Example

Captured a live DNS query, confirming the resolved IP and the local resolver (`127.0.0.53`) that answered it — matching a `dig` lookup performed separately.

## 🧪 Practical Example

Captured own port-scanner traffic with `tcp.flags.syn == 1`, correctly identified which ports completed the handshake (SYN-ACK reply) versus which received no reply or an ICMPv6 "Destination Unreachable."

## ⚠️ Common Mistakes

- Expecting to see a plaintext Certificate packet on a TLS 1.3 connection (it's encrypted as part of the handshake)
- Getting overwhelmed by unfiltered live capture instead of applying a specific filter immediately
