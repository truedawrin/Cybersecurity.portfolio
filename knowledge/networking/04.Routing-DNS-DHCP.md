# 📚 Routing, DNS, and DHCP

## 📌 Definition

Three services that make "just connecting to the internet" work invisibly: routing (getting packets to the right network), DNS (translating names to IPs), and DHCP (automatically assigning IP addresses).

## 🧠 Core Concept

None of these three protocols authenticate who they're talking to by default — they trust whichever device speaks first, which is the exact weakness attackers exploit (rogue DHCP, DNS spoofing).

## ⚙️ How It Works

**Routing:** a routing table decides where to forward a packet; the **default gateway** handles anything not on the local network.

default via 192.168.1.1 dev wlan0

**DNS resolution chain:** browser → local resolver (cached, often `127.0.0.53`) → root server → TLD server (`.com`) → authoritative nameserver → IP returned and cached.

**DHCP — the DORA process:**

Discover — device broadcasts "is there a DHCP server?"
Offer — server responds with an available IP
Request — device accepts that IP
Acknowledge — server confirms, IP is leased

## 🔐 Cybersecurity Relevance

DNS is a major recon source (subdomain enumeration). A **rogue DHCP server** can hand out itself as the gateway/DNS server without exploiting any vulnerability — purely by abusing DHCP's lack of authentication, enabling a silent man-in-the-middle position.

## 💻 Example

```bash
dig google.com          # full DNS resolution trace
ip route show           # default gateway
```

## 🧪 Practical Example

Ran `dig google.com`, identified the ANSWER, AUTHORITY, and ADDITIONAL sections, and traced which local resolver (`127.0.0.53`) handled the query first.

## ⚠️ Common Mistakes

- Assuming DNS answers are always trustworthy — cache poisoning and spoofing are real attack classes
- Not recognizing that DHCP's danger comes from a design assumption (trust), not a software bug

## 🧠 Key Takeaways

- Local network protocols (DHCP, and later ARP) share the same root weakness: no built-in authentication
- DNS caching is why repeated lookups for the same domain are near-instant after the first resolution
